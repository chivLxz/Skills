# OpenClaw Skills

My collection of OpenClaw agent skills.

## Skills

- [cn-ai-news-digest](./cn-ai-news-digest/) - 国内 AI 行业资讯日报，覆盖 7 个中文科技媒体
- [arch-mindmap](./arch-mindmap/) - 读懂项目/代码库，产出**多层、可编辑、说人话**的思维导图（Markdown 大纲 + .xmind + SVG / PNG / PDF）。主干深挖到 5~7 层但保留采样率/时延/阈值这类产品参数，剔除环境变量与函数名这类代码标识符；零第三方依赖
- [research-workflow](./research-workflow/) - 结构化调研交付：**文本结论出 Excel，视觉结论出带截图的 Word**。先做≥20 条候选网页的全域搜索定范围，再按内容形态分流；内建状态闸门，机械拒绝「已截止却标为可报名」的条目
- [edu-pm-workflow-v2](./edu-pm-workflow-v2/) - 产品需求全流程工作流 v2：把一句需求落成**可评审的 HTML PRD + 可交互原型 + 流程图 + 验收清单**。产出原型前必问「形态 / 来源 / 落点」，基于已有代码库**先侦察后实现**；**PRD 与原型代码强绑定**（产出 PRD 必须同步改代码，图必须是代码的真实渲染）；双栏预览**三级滚动同步**（页面 / 状态 / 元素）；**原型即产品**（不许出现"演示数据 / 仅供评审"横幅、导航栏评审标签、评审专用样式脚本）；PRD 右上角**六个固定导航**（双栏预览 / 编辑 / 撤销 / 保存 / 交互原型 / 静态图册），**编辑须登录**、游客只读，改动**留痕可溯**（谁 / 何时 / 改了什么 / 改在哪）；**内网托管**让同事在你浏览器之外也能登录编辑（真改在你的磁盘上），**服务端一键「重新出图」**按当前代码把落后的截图重出一遍（不需要 AI、不需要开终端）；**v2.7 修掉三个"机械校验全绿、真点一遍才发现是坏的"问题**：宿主页在项目根时一律 404；**v2.8 补上骨架三件套的机械校验**（照抄旧 PRD 会被拦住），并点名「单文件预览链接必然丢图」这一宿主限制（服务静态文件路由的目录白名单误伤）、骨架缺样式导致原型图撑爆表格 / 流程图 iframe 掉回 300×150、「重新出图」只有 `<button>` 没接实现；**v2.9 改判「主产物是什么」**——`prototype.html` 降级为兜底产物，用户给了历史代码时主产物就是被真实改动的宿主代码文件，全篇 35 处引用逐处挂上触发条件

### research-workflow 速览

四阶段流程，每阶段都有可执行的准入条件：

| 阶段 | 做什么 | 防的是什么 |
|---|---|---|
| Phase 1| 5 角度查询矩阵，候选池 ≥ 20 条，来源分 T1–T5 层 | 被搜索排序绑架，只调研前几条 |
| Phase 1.5 | 每个有截止期的条目锁定 `status`/`deadline`/`verified`/`source` | 已截止的赛事被当成可报名 |
| Phase 2 | 判断内容形态 → 出 Excel（可比较）或 Word+截图（须看见） | 强行把截图类内容塞进表格 |
| Phase 3 | `validate.py` 校验 → `build_all.py` 一份数据渲染两份文件 | Excel 与 Word 内容漂移 |
| Phase 4 | 8 项自检 + 校验器 exit 1 阻断 | 表名与内容矛盾、缺失字段 |

**两份交付物来自同一份数据**：`entries[].fields` 渲染成Excel 行，`entries[].doc` 渲染成 Word 章节，状态列由脚本自动注入—— 所以两者不可能对不上。

```bash
python scripts/validate.py data.json          # 有 ERROR 则禁止交付
python scripts/build_all.py data.json -o out.xlsx --docx out.docx
```

**依赖**：`openpyxl`、`python-docx`，截图需本机 Chrome /Chromium / Edge。无其他依赖。

**隐私**：`shoot.py` 只在本地启动无头浏览器截图，不上传任何内容；纯文本调研全程无需联网浏览器。

### edu-pm-workflow-v2 速览

产出一份 PRD 时要过的几道硬门禁：

| 门禁 | 要求 | 防的是什么 |
|---|---|---|
| 问三 · 落点 | 基于已有代码库时必问：**就地改宿主页** / **独立工作区 + `MERGE-NOTES.md`** / **新版本全量目录** | 「只出文档、代码一字节没动」——首次实战就是这样被用户判为不合格 |
| §3.7 先侦察后实现 | 动手前先定位宿主页、技术栈、命名风格、既有弹窗组件，并回报落点确认 | 把 from-scratch 默认套路（Tailwind / `.device` / 默认产出路径）盖到已有代码库上 |
| §3.9 图 ↔ 代码绑定 | PRD 的每张原型图必须是**本次真实改过的代码**渲染出来的，图 `mtime` ≥ 代码 `mtime` | 手绘 / 设计工具另做 / 别处拷来 / 上一版旧图 |
| §2.6 ⑧ 三级滚动同步 | 左侧滚到某行 → 右侧 L1 换页 / L2 进状态（弹窗、置灰、成功态）/ L3 高亮元素 | 「以为做了元素级同步、其实只到页面级」 |
| §3.10 原型即产品 | 原型渲染的每一屏都要跟"功能真上线后"一致；禁**免责横幅/角标**、**导航栏评审标签**、**评审专用样式脚本**、`?review=1` 这类声明。假数据靠数据本身辨认，不靠界面声明 | 「演示数据 · 此原型用于产品评审，非客户真实使用」横幅；导航栏挂「演示数据」标签；新增 `*-review-artifacts.css` |
| §2.10 顶栏六导航 | PRD 右上角固定**六个**导航（双栏预览 / 编辑 / 撤销 / 保存 / 交互原型 / 静态图册，顺序不许变）；**编辑必须登录**（本地导出服务内置账号），服务连不上 / 没配账号 / `PM_READ_ONLY` / `viewer` 角色**统一落进游客**、置灰只读；改动记录四列「修改人 / 修改时间 / 修改内容 / 位置」；六个导航右侧另设 `.topbar-tools` 工具区（竖线隔开，**不带 `data-pm-nav`**——它是「工具」不是「导航」） | 「只要能连上服务谁都能改」的假编辑；改完说不出改在哪；静态图册页与 PRD 页外壳不一致；交互原型页被塞进我方导航；「重新出图」被误加 `data-pm-nav` 变成第七个导航 |
| §2.9 内网托管 | 谁能编辑只看「**这台浏览器连不连得到那个服务 + 有没有账号**」，与「是不是那台机器本人」无关。`--lan` / `--host <内网IP>` 绑内网后，同事开 `http://<你的内网IP>:<端口>/` 登录即可编辑，保存真写在你磁盘上。防 DNS-rebinding 判据从「来源必须是 loopback」换成「**Host 头必须指向本机地址集合**」；可写托管前必须先有至少一个编辑账号，否则直接报错给建号命令；启动横幅如实打印代价（机器要一直开着 / IP 变了旧链接失效） | 「内网访客顶多是游客、保存只落本地副本」的假编辑（v2.5 口径，v2.6 已改判）；`evil.com` 解析到 127.0.0.1 的 DNS-rebinding；托上去才发现谁都编辑不了 |
| §2.11 重新出图 | 改了正文、或工程师改了原型代码，PRD 里的截图就旧了。服务端按**内容签名**（老清单退回 mtime）比对每张图与原型代码 → 落后的图在正文描琥珀虚线、按钮显示「· N 张待更新」→ 点一下由 Playwright 按当前代码重出 → 只给**这次真的重出过的**图打 `?v=` 时间戳。手工放进截图目录的图、源原型已删的图**不判不碰** | 图跟代码对不上却没人发现；截图靠人肉重出；给所有图无差别打时间戳导致缓存全失效 |
| §2.11 ⑤ 重新出图不是死按钮 | 「按钮在页面上」和「按钮能出图」是两件事：按钮要带 `hidden`，前端要**同时**接 `PMService.figureStatus()`（拉状态、给落后图描边）和 `PMService.refigure()`（点按钮真发请求），图册页同款按钮也要带 `hidden`。`validate_prd.py` 直接查这三条 | 只写了个 `<button id="navRefigure">`、没接 §2.10 ⑤ 那段 JS——机械校验全绿，点了没反应，用户以为文档坏了 |
| §2.2 骨架自带样式 | 骨架那块 `<style>` **不许删、不许另写一版更短的**：表格 `table-layout:fixed`、`.proto-shot` 不许写 `width=`（写死就绕过 CSS）、`.flow-frame` 必须给 height | `<img width="1600">` 包 3200px PNG 把四列表格撑到 `scrollWidth 1811 > 视口 1500`；流程图 iframe 没尺寸掉回浏览器默认 300×150 |
| §2.2 骨架三件套（v2.8） | 迭代旧 PRD 时**不许照抄上一版的结构**，只能从 `prd-content.html` 复制骨架；`validate_prd.py` 逐条点名 `table-layout:fixed` / `.proto-shot{max-width}` / `.flow-frame` height（只在文档真用到对应元素时才查那条） | 照抄上一版 → v2.7 补的三条样式一条都没进去 → 流程图 iframe 渲染成 **154px**（浏览器默认 300×150），校验器却全绿（它只查「有没有 `<style>`」） |
| §2.9 丙 · 单文件预览链接 | 编辑器预览面板只放行那一个 HTML，兄弟目录的图与流程图**必然取不到**——黄框报的是实话。判据：同一份 PRD 用本地服务打开，那批资源**全部 200**（实测开不开 `--lan` 都一样） | 把宿主环境限制当成 skill bug 去修；拿预览链接评审、以为图丢了 |
| §2.9 静态文件路由 | 服务能取到**项目根**上的宿主页及其 `.css`/`.js`（黑名单：项目根下 + 后缀允许 + 不碰点号目录与依赖目录）。越界仍由 `_is_under()` 挡，`users.json` 后缀不在允许列表里 | 目录白名单要求 URL 里必须出现产物目录名 → 「就地改宿主页」时宿主页一律 404 → 双栏预览空白、交互原型页 Not Found、一键复制全文丢图 |
| §3.8 原型不写「薄外壳」 | 用户给了宿主代码就**在宿主代码上改**，需要新增页面才新增、命名沿用宿主风格；判据一句话——**"这个文件产品上线后还会存在吗"** | 凭空造一层 `[需求名]-prototype-flow.html` + `<iframe>` 的跳转壳，既违反 §3.10 又多出一层产品没决定过的界面 |
| 主产物不固定为 `prototype.html`（v2.9） | `[需求名]/原型/[需求名]-prototype.html` **只是没有历史代码可依托时的兜底产物**。用户提供了历史版本代码 → 主产物是**被真实改动的那些宿主代码文件**，**不出** `prototype.html`；用户没提供任何可复用代码 → **才出**。判定不许猜：用户只要提到过一条具体路径（目录 / HTML / 仓库 / "上一版 / v1.4.1 / 现有页面"）就是「有历史代码」 | 规范里 `prototype.html` 出现 35 处且都在最前面（步骤三开头、§3.1 第 10 条、目录结构模板），AI 读到就默认要产出它 → 宿主代码改了旁边还多一份没人要的 `prototype.html`，或更糟：**只出了 prototype.html + 截图，宿主代码一字节没动** |

```bash
python assets/scripts/validate_prd.py "需求名/需求文档/需求名-PRD.html"   # 交付前必跑
py -3 scripts/start_service.py --add-user 张三     # 建编辑账号（局域网可写的前置条件）
py -3 scripts/start_service.py --lan               # 绑内网，同事可登录编辑（打印出链接）
py -3 scripts/start_service.py --read-only         # 只想给同事看、不需要编辑
```

**依赖**：Python 3.9+；截图引擎优先复用本机 Chrome / Edge，正常情况零下载。
